# Grok mode (`teamgrok`) — 2026-10-15

Owner request (2026-10-15): "teamproxy 에 grok 도 포함 시키고 selvi 에도 ai 연결에 그록도 포함 시키자".
A fourth, fully isolated provider pool next to Anthropic, Codex and agy mode, in this same codebase and install:
SuperGrok accounts used by xAI's **Grok Build CLI (`grok`)** and by other local clients (the Selvi app), rotated
like the other pools. Pattern to copy: agy mode (`docs/specs/2026-10-10-agy-mode.md`, `src/agy.js`).

## Facts (verified 2026-10-15 against grok 1.0.46 and a real SuperGrok account)

### Redirecting grok
- `GROK_CLI_CHAT_PROXY_BASE_URL=<url>/v1` makes grok send its whole backend traffic to `<url>/v1/...`. Default
  upstream base **`https://cli-chat-proxy.grok.com`** (the CLI appends `/v1`). A pass-through recorder there worked
  end to end (`grok -p "…"` → answer, every call 200). Token refresh goes straight to `https://auth.x.ai` (not via
  the proxy). `GROK_DISABLE_AUTOUPDATER=1` keeps it from updating itself mid-test.
- grok must be signed in locally (any account) to start; the proxy drops grok's own bearer and injects the pool
  account's (same rule as agy). Login-free run (`GROK_AUTH_PROVIDER_COMMAND`, …) is out of scope.
- Leader: `/v1/settings` says `leader_mode: false`; requests come from the `grok` process itself, so the env
  var on the process is enough.

### Calls seen (all under `/v1`, JSON unless noted)
`GET /v1/user`, `GET /v1/user?include=subscription`, `GET /v1/settings`, `GET /v1/models`, `GET /v1/bundle/archive`
(4 MB gzip; first try without auth → 401, then with auth), `GET /v1/feedback/config`, `POST /v1/responses`
(inference, `accept: text/event-stream`), `POST /v1/storage`, `POST /v1/traces` (OTLP protobuf),
`POST /v1/sessions/<id>/signals`, `POST /v1/sessions/<id>/turn-deltas`, `GET /` (404).
The binary also references `/v1/chat/completions`, `/v1/messages`, `/v1/billing`, `/v1/cursor/session`, `/v1/tools`.
**Forward any path generically; never allow-list.**

- Request headers from grok: `authorization: Bearer <JWT>`, `x-xai-token-auth: xai-grok-cli`,
  `x-grok-client-version: 1.0.46`, `x-grok-client-mode: interactive|headless`, `x-grok-client-identifier: grok-shell`,
  `user-agent: grok-shell/1.0.46 (macos; aarch64)`, `x-grok-model-override: grok-4.7`,
  `x-grok-session-id`, `x-grok-conv-id`, `x-grok-conv-group-id`, `x-grok-req-id`, `x-grok-agent-id`,
  `x-grok-turn-idx`, and **identity headers of the local login**: `x-userid`, `x-email`, `x-grok-user-id`, `x-teamid`.
- **Request bodies may be zstd-compressed** (`content-encoding: zstd`; `/v1/settings` lists
  `accept_request_encodings: ["zstd"]`). Forward bodies byte-identical; the proxy needs nothing from the body
  (model and session come from headers). If a body is ever read, decode zstd first (`zlib.zstdDecompressSync`,
  Node ≥ 23.8).
- `POST /v1/responses` is the OpenAI **Responses API**: `{model, input, tools, reasoning:{effort,summary},
  include:["reasoning.encrypted_content"], store:false, stream:true, prompt_cache_key}`. Response
  `text/event-stream` with standard `response.*` events; `response.completed` carries `usage`
  (`input_tokens`, `output_tokens`, `…_details`, `cost_in_usd_ticks`). The served model is e.g. `grok-4.7-build`.
- Response headers on inference: `x-ratelimit-limit-requests: 8300`, `x-ratelimit-remaining-requests`,
  `x-ratelimit-limit-tokens: 53000000`, `x-ratelimit-remaining-tokens`, `x-grok-context-window: 256000`,
  `x-request-id`. Remaining did not move over a handful of calls (window unknown). No reset header seen.
- `GET /v1/models` → `{object:"list", data:[{id:"grok-4.7", name, context_window, api_backend:"responses",
  reasoning_effort:"high", reasoning_efforts:[{value:"xhigh"|"high"|"medium"|"low",…}], …}, …]}` newest first
  (`grok-4.7`, `grok-4.7-build-fast`, `grok-4.6`, `grok-4.5`, …), no `created` field.
- `GET /v1/user?include=subscription` → `{userId, email, teamId, xUserId, hasGrokCodeAccess, subscriptionTier:
  "SuperGrokPro", …}`. `GET /v1/settings` → `subscription_tier_display: "SuperGrok Heavy"`, `min_client_version:
  "1.0.13"`, `default_model: "grok-4.7"`. `GET /v1/billing` → on-demand (pay-as-you-go) usage only
  (`monthlyLimit`, `used`, billing period) — not the subscription window.
- Upstream 401: `www-authenticate: Bearer error="invalid_token", error_description="Invalid or expired credentials …"`.

### Other clients (the Selvi app, curl) — verified
- Without `x-grok-client-version` every call answers **426** `{"error":"Your Grok CLI version (none) is outdated…"}`.
- With `x-grok-client-version: 1.0.46` and any user-agent (`selvi-probe/0.1` tested), all of these answer 200:
  `POST /v1/responses` streaming and non-streaming, `POST /v1/chat/completions` non-streaming
  (`choices[0].message.content`, `reasoning_content`). `x-xai-token-auth` is not required.
- So for a client that is not grok, the proxy fills a missing `x-grok-client-version` with the last value seen from
  grok (else config `grokClientVersion`, default `1.0.46`) — the same idea as agy's user-agent swap. The client
  never impersonates grok itself.

### Credentials (xAI OIDC, public client — no secret)
- Issuer `https://auth.x.ai`, discovery `/.well-known/openid-configuration`: token
  `https://auth.x.ai/oauth2/token`, device authorization `https://auth.x.ai/oauth2/device/code`, revocation
  `https://auth.x.ai/oauth2/revoke`; `token_endpoint_auth_methods_supported` includes `none`; grants
  `authorization_code`, `refresh_token`, `urn:ietf:params:oauth:grant-type:device_code`; PKCE S256.
- grok's client id: `b1a00492-073a-47ea-816f-4c329264a828` (the JWT `aud`; also `oidc_client_id` in
  `~/.grok/auth.json`). It is public (every token carries it), so it may live in code as the default; config
  `grokOAuthClientId` overrides.
- Device flow verified: `POST /oauth2/device/code` (`client_id`, `scope`) → `device_code`, `user_code`
  (`F2PW-4F88` shape), `verification_uri` `https://accounts.x.ai/oauth2/device`, `verification_uri_complete`,
  `expires_in: 1800`, `interval: 5`.
- grok's token scopes: `openid profile email offline_access grok-cli:access api:access conversations:read
  conversations:write workspaces:read workspaces:write` — request the same.
- Access token = ES256 JWT (~890 chars), lifetime 6 h (`exp - iat = 21600`), claims include `sub`, `principal_id`,
  `team_id`, `tier`, `client_id`. **Refresh tokens rotate** (verified 2026-10-15 after merge, see the end) — always
  store a returned `refresh_token`, keep the old one when none is returned.
- grok's own login lives in `~/.grok/auth.json` (`$GROK_HOME`): `{"https://auth.x.ai::<client_id>": {key (access
  token), refresh_token, expires_at, auth_mode:"oidc", user_id, email, team_id, oidc_issuer, oidc_client_id, …}}`.

## Requirements

### Provider wiring
Provider id `grok`. Selected by `TEAMCLAUDE_PROVIDER=grok`, the `grok` subcommand prefix, or config
`provider: "grok"` — same mechanics and mode/config agreement as `agy`. Own config `~/.config/teamgrok.json`,
default port **3459**, own state files; pool label "TeamGrok". Anthropic, Codex and agy behaviour must not change.
Zero runtime dependencies (repo hard constraint).

### CLI (`src/index.js`, mirror the `agy` prefix)
- `grok server|stop|restart|status|accounts|remove|reload|enable|disable|priority|env` like their agy twins, with the
  same `--json` forms app mode uses (`app-json.js`).
- `grok login [--name N] [--json]`: **device flow** with the resolved client id and the scopes above — print (or
  emit) `verification_uri_complete` + `user_code`, try to open the browser with the existing helper, poll the token
  endpoint at `interval` (`authorization_pending` → keep polling, `slow_down` → +5 s, `expired_token` /
  `access_denied` → fail). `--json` emits the same event stages other pools emit (`auth_url` with the URL and the
  user code, `waiting`, `done`, errors such as `name_taken`) so the Selvi app's existing login UI (it already shows a
  `userCode`) works unchanged. Default names `grok-1`, `grok-2`, …
- After login: `GET <upstream>/v1/user?include=subscription` with the new token (+ `x-grok-client-version`) →
  store `userId` (identity key; re-login of the same user updates in place, never duplicates), `email`, `teamId`,
  `subscriptionTier`. Warn (do not fail) when `hasGrokCodeAccess` is false.
- `grok import [--name N] [--file P]`: import grok's own login from `~/.grok/auth.json`. **Warn** that pool and
  grok then share one refresh token (if xAI rotates refresh tokens, one side gets signed out) and recommend `login`.
- `grok run [-- <grok args>]`: auto-start the server like agy's `run`, then spawn grok with
  `GROK_CLI_CHAT_PROXY_BASE_URL=http://127.0.0.1:<port>/v1` and the user's normal environment. Binary:
  `TEAMGROK_GROK_BIN` → `$GROK_HOME/bin/grok` (default `~/.grok/bin/grok`) → `$HOME/.local/bin/grok` → bare `grok`;
  ENOENT names the resolved path. Document that one local `grok login` is needed once.
- Never revoke refresh tokens (`remove`, re-login).

### Proxy (`src/server.js` + `src/account-manager.js`)
- Upstream `https://cli-chat-proxy.grok.com` (config `grokUpstream`, falls back to `upstream`, which a new
  `teamgrok.json` writes like the other modes).
- Strip client `authorization`, `x-api-key`, `cookie`; inject `Bearer <account token>`. Keep everything else.
- Fill a missing `x-grok-client-version` (rule above). Remember the last value seen from a request whose
  user-agent starts with `grok-shell/`.
- **Identity headers**: when a request carries `x-userid`, `x-grok-user-id`, `x-email` or `x-teamid`, rewrite them
  to the selected account's stored `userId` / `email` / `teamId` (drop `x-teamid` when the account has none). Never
  add them to a request that did not carry them. Applies to failover retries too.
- Refresh routed by `account.provider === 'grok'`: `POST https://auth.x.ai/oauth2/token` form
  `grant_type=refresh_token&refresh_token&client_id` (no secret), existing coalescing / 5-min early refresh,
  `invalid_grant` → existing terminal-auth park path. An upstream 401 with `error="invalid_token"` → refresh once
  and retry like the other modes.
- Quota: record `x-ratelimit-{limit,remaining}-{requests,tokens}` from every response that carries them, per
  account. Unified meter (status, TUI, footer, app `accounts --json`) = `max(1 − remaining/limit)` over requests and
  tokens; no reset time is known, so no window bars beyond that. No proxy-originated polling is needed (nothing to
  poll); `reload` re-reads `/v1/user?include=subscription` for the tier only.
- Exhaustion (not observed yet — design defensively, like agy): a 429 on an inference path (`/v1/responses`,
  `/v1/chat/completions`, `/v1/messages`) marks the account throttled until `retry-after` (seconds or HTTP date) or
  else 5 min, and the same request fails over at once to another account; with no account left, the upstream 429
  body passes through unchanged (grok renders its own message). A 429 elsewhere → no account state, pass through.
- Session stickiness: grok keeps server-side session state (`/v1/sessions/<id>/…`, `/v1/storage`), so switch
  accounts only when the current one cannot serve. Affinity key: `x-grok-session-id` (non-empty), else
  `x-grok-conv-id`, else the `<id>` of `/v1/sessions/<id>/…`, else the socket — reuse the existing bounded key map.
- SSE and every other body pass through untouched (no synthetic frames).
- Loopback-only like agy (a remote client needs the proxy key, as the supervisor already enforces).

### Footer and app mode
- `src/hud/launcher.py --grok`: `teamgrok` with no args or `-` flags opens grok inside the private tmux server
  `teamgrok-hud` with the account footer (meter above, tier, account name), like `--agy`. Print-mode flags that
  skip the footer: `-p`, `--single`, `--prompt-file`, `--prompt-json`, `-v`, `--version`, and the subcommands `agent`,
  `models`, `version`. `--yolo` → grok's `--always-approve`. Shift+Enter → `M-Enter` (grok: "Insert newlines with
  Shift+Enter or Alt+Enter"). Tab title "Grok".
- `scripts/install-app.mjs`: add pool `grok` (`teamgrok`, port 3459, `teamgrok.json`, launchd
  `kr.selvi.teamproxy.grok`), `--pools` usage text, `--login-command grok` → `teamgrok login --name grok-N`. The app
  bundle (`scripts/build-app-bundle.mjs`) must include everything grok mode needs.
- `scripts/install.py` / `docs/install/*`: add teamgrok next to teamagy where the others are listed.

### Out of scope (say so in docs)
Login-free run, xAI API-key mode (`api.x.ai`, that is the Selvi app's own direct path), mid-stream recovery,
subscription billing / on-demand caps, non-macOS keychain.

## Implementation decisions (2026-10-15, as built)

- **Meter is display-only.** `x-ratelimit-*` from every grok response lands in `quota.grokRateLimit`
  (`requestsLimit/Remaining`, `tokensLimit/Remaining`, `utilization`, `at`); `utilization` (the fuller of the two) mirrors
  into `unified5h` so status, TUI, footer and `accounts --json` (`fiveHour.usedPct`) show it. `_isNearQuota` never gates a
  grok account: with no reset time a gate on the meter could never lift. Only an inference 429 takes an account out.
- **429.** Inference path → `markRateLimited` for `retry-after` (seconds or HTTP date, the server's existing
  `parseRetryAfterMs`; absent or 0 → 5 min, no 5-minute clamp as in the generic path) and an immediate failover that does
  not count against `rateLimitFailovers`. Any other path → no account state and **no failover** (spec: pass through),
  unlike agy's bounded capacity failover. Nothing left → this request's upstream 429 replayed byte-identical with its
  headers. A pre-dispatch dead end (every account already throttled) replays nothing it has not seen: it answers
  `429 {"error": "TeamGrok pool exhausted: …"}` (xAI's own `{"error": string}` shape, as in the 426) with `retry-after` =
  soonest throttle (1 s when only concurrency-capped, else 60 s). The proxy-made 401 (every account failed auth) uses
  the same `{"error": …}` shape.
- **401.** The generic path: any upstream 401 → one forced refresh and a retry on the same account, then the existing
  park/cascade rules. Not narrowed to `error="invalid_token"` (the only 401 seen).
- **Identity headers.** Matched case-insensitively, rewritten on every attempt (so a failover carries the new account's
  identity). A header the account has no value for is dropped — `x-userid`/`x-email` as well as `x-teamid` — so a local
  login's identity never reaches upstream next to another account's token.
- **Client version.** Filled once on the incoming request. Remembered only from a request that has a `grok-shell/`
  user-agent **and** the header; a foreign client's own version is forwarded but never remembered. Order: last seen →
  config `grokClientVersion` → `1.0.46`. Proxy-originated calls (`reload`) carry the same value.
- **Accounts.** Identity = `/v1/user?include=subscription` `userId`, else the login's own (`auth.json` `user_id`, else the
  JWT `sub`). Name: `--name` → the existing name of the same `userId` → first free `grok-N`. A name match with another
  user is replaced but inherits nothing (no tier). Stored per account: `accountUuid` (userId), `email`, `teamId`,
  `planType` (= `subscriptionTier`, the field status / app `plan` / footer already show), tokens, `expiresAt` (JWT `exp`,
  else `expires_in`, default 6 h; `auth.json` `expires_at` read as seconds/ms/date when the JWT has none). `/v1/user`
  failing only warns (tier unknown). `hasGrokCodeAccess: false` warns.
- **Device flow.** Default `interval` 5 s, `slow_down` +5 s, deadline `expires_in` (default 1800 s). App mode emits
  `{"event":"auth_url","url":<verification_uri_complete>,"user_code":"…","browser_opened":false}` then `waiting` (the
  shape Codex `--device-auth` already uses), never `need_code`; `expired_token` maps to `login_timeout`,
  `access_denied` to `oauth_denied` (existing `errorCode` patterns). Interactive mode prints the code and opens the
  browser with the existing helper.
- **Import.** `--file` (default `$GROK_HOME/auth.json`, `~/.grok/auth.json`): the entry keyed `…::<client id>` (or with
  that `oidc_client_id`), else the only entry with a token. Refreshed first only when expiring. The shared-refresh-token
  warning goes to stderr.
- **Defaults.** New configs: port 3459, `upstream` `https://cli-chat-proxy.grok.com`, `maxConcurrentPerAccount` 8 (grok
  fires storage/traces/signals beside each response, like agy); server `reevalIntervalMs` defaults to 0; accounts are
  always "measured" (no warm-up hopping). Continuity and stream recovery stay off (worker and supervisor).
- **`reload`** re-reads tiers of enabled, un-parked accounts into the live `planType` (the config is not rewritten; the
  next login/import stores it). A SIGHUP account reload does not call `/v1/user`.
- **`accounts`** without a running server refreshes an expiring grok token through xAI (as Codex does) before listing.
- **Footer.** `launcher.py --grok`: one `RL` bar, plan column = tier, no `7d`/`End`; skip flags `-p --single
  --prompt-file --prompt-json -v --version` and subcommands `agent models version`; `--yolo` → `--always-approve`;
  Shift+Enter → `M-Enter`; window/tab title `Grok`; socket `teamgrok-hud`.
- **App mode.** `install-app.mjs` pool `grok` (`teamgrok`, 3459, `teamgrok.json`, `kr.selvi.teamproxy.grok`, wrapper
  `-u TEAMCLAUDE_SESSION_SUPERVISED TEAMCLAUDE_PROVIDER=grok … src/index.js grok`). `--app` without `--pools` now installs
  all four pools. The bundle needs no change (it ships every tracked `src/` file, `src/grok.js` included).
  `scripts/install.py` lists no agy pool either, so it is unchanged; `docs/install/INSTALL-ALL.md` §1-4 has the wrapper.
- **Review fixes (2026-10-15).** A `/v1/sessions/<id>` with a malformed %-escape keys affinity by the raw `<id>`
  (it used to throw and leave the socket unanswered). The device poll uses 5 s when `interval` is not a finite number
  and retries a network error or 5xx at the next interval until the deadline. `auth.json`'s lone-entry fallback refuses
  a login issued to another `oidc_client_id` (its refresh token would not refresh with ours), and an unparsable file
  gets a fixed message that never quotes its content. `teamgrok status` prints `Rate limit used: x%`; the TUI shows
  `Req`/`Tok` bars from `grokRateLimit`. The package (app bundle) version is 1.4.0 so app-mode installs reinstall every
  pool.
- **Not done:** upstream 5xx bodies on a POST are still replaced by the shared Anthropic-shaped `overloaded_error` JSON
  (same as Codex/agy); WebSocket upgrades are not proxied.
- **Not verified against a real account (fake endpoints only):** the shape and headers of a real exhaustion 429
  (`retry-after`?), whether `/v1/user` `userId` equals the JWT `sub`, and the type of `auth.json` `expires_at`.

## Verified after merge (2026-10-15, real SuperGrok account, owner's Mac)
- `teamgrok login --name grok-1`: device flow → the owner approved the code in the browser → account stored
  (`SuperGrokPro`), config `0600`.
- Forced refresh (expiry moved into the past, then `teamgrok accounts`): `POST https://auth.x.ai/oauth2/token` with the
  public client id and **no secret** answered 200 with a new access token (6 h) **and a new refresh token** — xAI
  rotates refresh tokens on every refresh. So `import` of grok's own login really does sign one side out later; use
  `login` (its own grant) for pool accounts.
- Through the proxy on `127.0.0.1:3459` with no client key: `GET /v1/models`, `POST /v1/responses` (stream and JSON),
  `POST /v1/chat/completions` (a client `Authorization` is stripped) all 200; `teamgrok run -- -p …` answered through
  the pool. No token in the server log.
