# Antigravity mode (`teamagy`) — 2026-10-10

Owner request (2026-10-10): "teamclaude, teamcodex 와 같이 teamagy 로 같은 방식으로 프록시 사용하고 싶어".
A third, fully isolated provider pool next to Anthropic mode and Codex mode, in this same codebase and install:
Google AI Pro/Ultra accounts used by the **Antigravity CLI (`agy`)**, rotated on quota like Codex mode rotates
ChatGPT accounts.

Why not Gemini CLI: since 2026-06-18 Gemini Code Assist refuses personal accounts for the Gemini CLI client
(`loadCodeAssist` → free tier `UNSUPPORTED_CLIENT … migrate to the Antigravity suite`, verified 2026-10-10).

## Facts (all verified 2026-10-10 against agy 1.3.3 and a real Google AI Pro account)

### Redirecting agy
- `CLOUD_CODE_URL=<url>` makes agy send every Cloud Code call to `<url>` (log line
  `Overriding CloudCodeServerURL via CLOUD_CODE_URL environment variable`). The default upstream is
  **`https://daily-cloudcode-pa.googleapis.com`**. A pass-through proxy at `CLOUD_CODE_URL` worked end to end
  (`agy models`, `agy -p … → OK`, every call 200).
- agy must be signed in locally (any account); the proxy drops agy's own bearer and injects the pool account's.
  A login-free run via `AGY_ADC_AUTH=1` + fake ADC does reach the proxy but agy then refuses to list models
  ("Auth mode is unspecified" → `plan model not specified`), so login-free is **not** supported.
- agy sends `Accept-Encoding: gzip` and upstream answers gzip; pass bodies/encodings through as the existing modes do
  (any proxy-side JSON parse of a response must decode first).
- agy does **not** compress request bodies: measured request headers carry no `content-encoding`, and bodies are
  plain JSON (so the proxy can read `model`, `project`, `requestId`, `trajectoryId` directly).

### Calls seen (all `POST /v1internal:<method>`, JSON, no extra headers besides authorization/user-agent)
`loadCodeAssist`, `fetchUserInfo`, `fetchAdminControls`, `retrieveUserQuotaSummary`, `fetchAvailableModels`,
`listExperiments`, `writeTrajectoryAcls`, `streamGenerateContent?alt=sse`, `recordTrajectoryAnalytics`.
The binary references many more (`retrieveUserQuota`, `onboardUser`, `countTokens`, remote/instance/signaling
methods, `GET /v1internal/<op>`…). **Forward any `/v1internal…` path generically**; never allow-list.

- User-Agent: `antigravity/cli/1.3.3 (aidev_client; os_type=darwin; arch=arm64; cl=996823801; auth_method=consumer)`.
- `loadCodeAssist` request `{"metadata":{"ideType":"ANTIGRAVITY"}}`; response (AI Pro):
  `{"currentTier":{"id":"free-tier","name":"Antigravity","upgradeSubscriptionType":"GOOGLE_ONE"},
    "paidTier":{"id":"g1-pro-tier","name":"Google AI Pro",…},"cloudaicompanionProject":"aicode-consumers",
    "allowedTiers":[…],"gcpManaged":…,"upgradeSubscriptionUri":…}`. Ultra is expected to be `g1-ultra-tier`.
- Every other body carries `"project":"aicode-consumers"` (shared consumer project, same for every consumer account).
  Rule: if the selected account has a stored `projectId` and the body's top-level `project` is a different string,
  rewrite it; otherwise leave the body byte-identical.
- `streamGenerateContent` request top-level keys: `project`, `requestId`
  (`agent/<conversationId>/<ms>/<trajectoryId>/<n>` or `checkpoint/<uuid>`), `request` (`contents`,
  `systemInstruction`, `tools`, `labels`, `generationConfig`, `sessionId`), `model` (e.g. `gemini-3.6-flash-low`),
  `userAgent:"antigravity"`, `requestType` (`agent`|`checkpoint`).
  Response `text/event-stream`, frames `data: {"response":{"candidates":[…],"usageMetadata":{…},"modelVersion":…,
  "responseId":…},"traceId":…,"metadata":{}}\n\n`; the last candidate has `finishReason`. No quota headers.
- `writeTrajectoryAcls` `{"trajectoryId":"<uuid>"}` → `{}`.

### Quota — `POST /v1internal:retrieveUserQuotaSummary {"project":"aicode-consumers"}`
```json
{"groups":[
  {"displayName":"Gemini Models","description":"Models within this group: Gemini Flash, Gemini Pro",
   "buckets":[{"bucketId":"gemini-weekly","window":"weekly","resetTime":"2026-10-17T03:33:37Z","remainingFraction":1},
              {"bucketId":"gemini-5h","window":"5h","resetTime":"2026-10-10T08:33:37Z","remainingFraction":1}]},
  {"displayName":"Claude and GPT models","description":"Models within this group: Claude Opus, Claude Sonnet, GPT-OSS",
   "buckets":[{"bucketId":"3p-weekly","window":"weekly",…},{"bucketId":"3p-5h","window":"5h",…}]}],
 "description":"Within each group, models share a weekly limit and a 5-hour limit. …"}
```
This maps 1:1 onto the existing unified 5h/7d model, **per group**. Group of a request = from its `model`:
`gemini-*` → `gemini`; `claude-*`, `gpt-*` → `3p`; anything else → `gemini`. `fetchAvailableModels` also returns a
per-model `quotaInfo {remainingFraction, resetTime}` (informational).
Model ids seen: `gemini-3.8|3.7|3.6-flash-{high,medium,low}`, `gemini-3.1-pro-{high,low}`, `gemini-3.5-flash-lite`,
`claude-opus-5-5-{low,medium,high}`, `claude-sonnet-5-5-{…}`, `gpt-oss-120b-medium`.

### Exhaustion (not observed yet — design defensively)
Expect Google RPC JSON 429 `{error:{code:429,status:"RESOURCE_EXHAUSTED",details:[ErrorInfo{reason},RetryInfo{retryDelay}]}}`
(same family as Gemini CLI). Treat any 429 on an inference call as "this account's group is exhausted": refresh that
account's summary at once, mark (account, group) unavailable until the summary's exhausted bucket `resetTime`
(fallback: RetryInfo delay, else 5 min), fail over to another account for the same request. `MODEL_CAPACITY_*`
reasons = Google capacity → no account throttle, bounded failover, then pass through. When no account can serve the
group, return the upstream 429 body unchanged (agy renders its own message).

### Credentials
- agy stores its login in the macOS keychain: service `gemini`, account `antigravity`, value
  `go-keyring-base64:<base64 JSON>` with JSON `{"token":{"access_token","token_type":"Bearer","refresh_token",
  "expiry":"<RFC3339>"},"auth_method":"consumer","id_token":"<JWT>"}`. Read with
  `/usr/bin/security find-generic-password -s gemini -a antigravity -w` (no prompt: go-keyring writes via
  `/usr/bin/security`). id_token payload gives `email`, `sub`, `aud`.
- OAuth client = the id_token `aud` (`1071006060591-…apps.googleusercontent.com`) + a `GOCSPX-` secret embedded in the
  agy binary. Refresh = `POST https://oauth2.googleapis.com/token` `grant_type=refresh_token&refresh_token&client_id&
  client_secret` → 200 (verified). Refresh tokens do not rotate.
- Granted scopes: `openid email profile https://www.googleapis.com/auth/{aicode,cclog,cloud-platform,
  experimentsandconfigs,userinfo.email,userinfo.profile}`.
- **The repo is public with GitHub push protection: never commit the client secret (or id).** Resolve them at
  runtime: config `agyOAuthClientId` / `agyOAuthClientSecret` in `~/.config/teamagy.json` (0600) if set; else scan
  the resolved agy binary once — client id = the `aud` of an imported id_token, or the
  `\d+-[a-z0-9]+\.apps\.googleusercontent\.com` that starts with `1071006060591-`; secret = see below — and cache
  both into the config. Tests use fake values and a fake binary.
- **Correction (2026-10-10, real-account end-to-end check): the bytes alone cannot pick the secret.** agy 1.3.3 holds
  `GOCSPX-` twice: (1) the head of a 70-byte run — Go stores strings back to back with no separator — whose first 35
  bytes are the secret of the `1071006060591-` client; (2) a free-standing 35-byte secret of another client. A scanner
  requiring "exactly 28 then a boundary" picked (2); once the access token lapsed every refresh answered
  `401 invalid_client` and the account was parked (`All 1 accounts failed authentication`).
  **Verified test:** `POST https://oauth2.googleapis.com/token` with `grant_type=refresh_token`, a bogus
  `refresh_token`, `client_id`, `client_secret` answers `400 invalid_grant` for the right pair and `401 invalid_client`
  for a wrong one (both measured; no side effect). So every `GOCSPX-` + 28 `[A-Za-z0-9_-]` (heads of longer runs
  included) is a candidate, every candidate is probed, and exactly one accepted pair is cached; none or several is an
  error asking for `agyOAuthClientSecret`.

## Requirements

### Provider wiring
Provider id `agy`. Selected by `TEAMCLAUDE_PROVIDER=agy`, the `agy` subcommand prefix (`node src/index.js agy <cmd>`),
or config `provider: "agy"` — same mechanics as `codex` (as built: the config `provider` must agree with the
mode, see "Mode/config agreement" below). Own config `~/.config/teamagy.json`, default port **3458**,
own quota/server-state files; pool label "TeamAgy". Anthropic and Codex behaviour must not change.
Zero runtime dependencies (repo hard constraint).

### CLI (`src/index.js`, mirror the `codex` prefix)
- `agy server|stop|restart|status|accounts|remove|reload|enable|disable|priority|env` like their codex twins where
  one exists. Codex-only features (subscription, reset credits, resume, cmux) are not offered for agy.
- `agy import [--name N]`: import the current agy keychain login (macOS); `--file <path>` imports the same JSON shape
  from a file (other OSes / tests). Identity key = id_token `sub` (re-import updates in place, never duplicates).
  After import call `loadCodeAssist` once and store `tierId` (`paidTier.id ?? currentTier.id`) and `projectId`.
  Warn (do not fail) when the account has no `paidTier`.
- `agy login [--name N]`: Google OAuth installed-app flow with the resolved client — PKCE, loopback redirect
  `http://127.0.0.1:<random>/…`, `access_type=offline`, `prompt=consent`, the scopes above; reuse the existing
  browser-open/print-URL and PKCE helpers. Then the same identity + `loadCodeAssist` step as import. This is how a
  second, third… account gets in without disturbing agy's own keychain login.
- `agy run [-- <agy args>]`: auto-start the server like Claude's `run` does (`ensureProxyRunning`; correction:
  `codex run` does **not** auto-start — `runCommand` skips `ensureProxyRunning` in Codex mode), then spawn agy with
  `CLOUD_CODE_URL=http://127.0.0.1:<port>` and the user's normal environment (agy keeps its own login, settings,
  MCP). Binary: `TEAMAGY_AGY_BIN` → `agy` next to `process.execPath` → `$HOME/.local/bin/agy` → bare `agy`;
  ENOENT names the resolved path. If agy is not signed in it will ask interactively — document that one local
  `agy` login is required once.
- Never revoke refresh tokens (`remove`, re-import). The local agy login may be the same account.

### Proxy (`src/server.js` + `src/account-manager.js`)
- Upstream `https://daily-cloudcode-pa.googleapis.com` (config `agyUpstream`, used by tests; falls back to `upstream`,
  which a newly created `teamagy.json` writes like the other modes).
- Strip client `authorization`, `x-api-key`, `x-goog-api-key`, `x-goog-user-project`; inject `Bearer <account token>`.
  Keep agy's user-agent (another client's is replaced — see "Other clients" below).
- Project rewrite rule above, on every forwarded JSON body including failover retries.
- Refresh routed by `account.provider === 'agy'` with existing coalescing / 5-min early refresh; `invalid_grant` →
  existing terminal-auth park path.
- Quota: per-account `retrieveUserQuotaSummary` at startup, every `warmupIntervalMs` (agy default ≥ 10 min — keep
  proxy-originated traffic low), and after a completed inference when the data is older than an active interval
  (mirror `codexUsageActiveMs`, default 2 min). Proxy-originated calls use the most recent client user-agent seen,
  else the literal above. Store both groups; selection for a request uses its group's 5h/weekly buckets with the
  existing `switchThreshold` / use-or-lose ordering. Status/TUI unified meter = the `gemini` group (5h → session,
  weekly → 7d); show the `3p` group alongside.
- Session stickiness: agy keeps server-side state per account (trajectory ACLs, conversations, remote instances), so
  switch accounts only when the current one cannot serve the group. If the existing session-affinity mechanism can
  key cheaply, key inference on `request.sessionId` and `writeTrajectoryAcls` on `trajectoryId`; otherwise rely on
  sticky active-account selection and say so.
- Non-inference calls (`loadCodeAssist`, `fetchAvailableModels`, `retrieveUserQuotaSummary`, `listExperiments`, …)
  go to the currently active account so agy shows the pool's real quota and tier.
- SSE passes through untouched — no Anthropic synthetic `overloaded_error` frames for agy.
- A remote (non-loopback) client must present the proxy API key like other modes; agy cannot send one, so agy mode
  stays loopback-only unless the existing config explicitly allows remote — pick the smaller change and document.
  Implemented as no change: the supervisor already rejects a non-loopback request without the proxy key.

### Out of scope (say so in docs)
Login-free run (ADC), Gemini CLI, API-key/Vertex modes, mid-stream synthetic recovery, reset credits, subscription
tracking, cmux resume, non-macOS keychain import (use `--file`).

## Implementation decisions (2026-10-10, as built)

Where the code had to decide something the facts above leave open:

- **Quota groups in `AccountManager`.** `quota.agyGroups = { gemini, 3p }`, each `{ fiveHour, weekly, blockedUntil }`
  with utilization `1 - remainingFraction`. The `gemini` group is mirrored into `unified5h/7d` (status, TUI, ordering).
  A request's group comes from its top-level `model` (`agyModelGroup`); a request **without** a model
  (`loadCodeAssist`, `fetchAvailableModels`, `retrieveUserQuotaSummary`, …) has no group and is never quota-gated, so
  agy can always read the pool's tier and quota even when every Gemini bucket is spent. A `3p` request also orders
  candidates by the `3p` buckets (`_orderQuota`).
- **A missing `remainingFraction`** (proto3 omits zero) reads as *unknown* in a routine summary (never blocks), and
  as *exhausted* in the summary fetched right after an exhaustion 429 (that bucket's `resetTime` becomes
  `blockedUntil`). Wrongly treating unknown as zero would park a healthy account for up to a week; the 429 path is
  self-correcting at the cost of one rejected request per reset window.
- **429 handling.** Exhaustion (inference path `streamGenerateContent`/`generateContent`, non-capacity reason): `blockedUntil = now + RetryInfo || 5 min`
  synchronously, then a fire-and-forget summary refresh moves it to the exhausted bucket's reset; the request fails
  over at once. Capacity (`MODEL_CAPACITY_*`) and any 429 on a model-less or non-inference call: no account state, at most
  `rateLimitFailovers` (default 1) alternates, then the upstream 429 passes through. When this request has no upstream
  429 to replay (every account already blocked before dispatch), the proxy answers a Google RPC shaped 429
  (`RESOURCE_EXHAUSTED` + `RetryInfo`) instead of the Anthropic-shaped one.
- **Session stickiness.** Without timer re-prioritisation (`reevalIntervalMs` defaults to 0 in agy mode), agy accounts
  count as always "measured" (no cold-start warm-up hopping, affinity applies from the first request), and the
  existing affinity is keyed cheaply: the trajectory id (`writeTrajectoryAcls.trajectoryId`, or the 4th segment of
  `requestId = agent/<conversation>/<ms>/<trajectory>/<n>`) so an ACL write and its inference land on one account,
  else `request.sessionId`, else the socket (bounded 1024-entry key map). New agy configs default
  `maxConcurrentPerAccount` to 8 so agy's parallel control calls do not spill a session onto another account.
- **Exhaustion refresh is never dropped.** If another summary refresh for the account is in flight when the 429
  lands, the exhaustion refresh is queued and runs right after it (the in-flight one predates the 429).
- **Polling scope.** Disabled (`enabled: false`) and parked (`status: error`) accounts are not polled.
- **Mode/config agreement (review 2026-10-10).** agy mode = the `agy` prefix or `TEAMCLAUDE_PROVIDER=agy`. Before any
  command runs, agy mode accepts an existing config only when it says `provider: "agy"` — a missing `provider` is
  refused too, because the real Claude config on the owner's machine has no provider key (5 accounts, none tagged) —
  and only a missing file is created (with `provider: "agy"`). A Claude/Codex mode with a `provider: "agy"` config is
  refused. The agy config writers and the worker's live reloads apply the same rule. Recommended wrapper: `teamagy` =
  `TEAMCLAUDE_PROVIDER=agy TEAMCLAUDE_CONFIG=~/.config/teamagy.json node src/index.js agy "$@"`.
- **Error shapes.** Proxy-made 401 (every account failed auth) and the pre-dispatch dead-end 429 use the Google RPC
  shape; the dead end's `retry-after`/`RetryInfo` is the soonest group recovery.
- **Secret selection by probe.** Candidates = every `GOCSPX-` + 28 secret-alphabet bytes (deduplicated), ids = the
  configured/`aud` id or every scanned `1071006060591-…` id; each pair gets the bogus-refresh probe above (also when
  there is a single candidate). Exactly one `invalid_grant` pair is cached; none, several, or an unclear answer
  (5xx, network) is an error asking for the config values — never a guess.
- **`invalid_client` on a refresh is the client's fault, not the account's.** `_refreshAgy` drops the cached secret,
  re-resolves once (`agyOAuthRecover`: a hand-edited secret on disk wins, else the probe without the refused secret;
  coalesced across accounts, 5-minute pause after a failed attempt), caches the result and retries. If the client is
  still refused, only that refresh fails: a still-valid token keeps serving, a lapsed one becomes `refresh-failed`
  (healed by the next successful refresh), never `auth-revoked`. `invalid_grant` alone remains the account verdict.
  `import` retries its pre-`loadCodeAssist` refresh the same way.
- **Token totals.** `usageMetadata.totalTokenCount` of the final frame (a candidate with `finishReason`) is recorded:
  `promptTokenCount` as input, the rest as output.
- **No continuity / stream recovery.** `continuityMode` defaults off, `streamRecovery` is off in both the worker and
  the supervisor relay, so SSE bytes pass through unchanged.
- **OAuth client.** `agyOAuthClientId`/`agyOAuthClientSecret` config → else id_token `aud` + a byte scan of the agy
  binary verified by the token-endpoint probe (`locateAgyBinary`: same resolution as `agy run`, PATH lookup for a bare
  name), cached into the 0600 config by
  `import`, `login`, and the server start. Test hooks: `agyTokenUrl`, `agyAuthUrl` (config),
  `TEAMAGY_SECURITY_BIN`, `TEAMAGY_AGY_BIN` (env).
- **`agy run` / worker launch** pass the `agy` prefix explicitly (an entry point such as `src/teamclaude.js` clears
  `TEAMCLAUDE_PROVIDER`).
- **`agy run` child env** drops `TEAMCLAUDE_PROVIDER` and `TEAMCLAUDE_CONFIG`, so a `teamcodex`/`teamclaude` that agy
  spawns is not silently pointed at the TeamAgy pool.
- **Other clients (the Selvi app, curl) — 2026-10-10.** The Selvi desktop app's Gemini card can send Cloud Code
  requests (`POST /v1internal:generateContent` / `streamGenerateContent?alt=sse`, body `{model, request:{contents,
  systemInstruction, generationConfig}}`) to teamagy. Measured that day: the same body with a non-agy user-agent
  (curl's default) gets upstream **403 `SUBSCRIPTION_REQUIRED`** ("…try using the latest version and logging in
  again (#3501)"); with agy's user-agent it gets 200 (`{"response":{…},"traceId":…}`, SSE frames
  `data: {"response":…}`). So, in agy mode:
  - A request whose `user-agent` does not start with `antigravity/` (or has none) is forwarded with the latest real
    agy user-agent seen, else the literal above. Only an `antigravity/…` user-agent is remembered, so a foreign
    client never becomes the user-agent of proxy-originated calls. The swap is made on the incoming request once,
    so every failover/retry attempt carries it. agy's own requests are untouched.
  - On an inference call (`generateContent` / `streamGenerateContent`), a missing or empty top-level `project` is
    filled with the selected account's `projectId`, else `aicode-consumers`; an existing project follows the
    rewrite rule above. Other methods are never filled: their bodies (`loadCodeAssist`, `writeTrajectoryAcls`) have
    no project, and `countTokens`' Cloud Code request (`{request:{model, contents}}`) has no `project` field.
  - A client's `authorization` / `x-api-key` / `x-goog-api-key` / `x-goog-user-project` are dropped as for agy;
    the account bearer is injected.
- **Not done:** upstream 5xx bodies on a POST are still replaced by the shared Anthropic-shaped `overloaded_error`
  JSON (same as Codex mode); WebSocket upgrades (if agy's remote/signaling methods use them) are not proxied.
